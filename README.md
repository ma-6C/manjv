# 漫剧工坊

Windows 本地视频制作工作台。当前主线基线为 **0.8.6**，用于已有剧集的素材导入、选集下载、字幕处理、重组分集、封面与工程材料制作。

本仓库存放主程序源码、测试与构建脚本。安装包、独立离线 AI 引擎、运行环境、用户工程、账号登录态和发行私钥在本地单独保存。

## 版本与工作流程

- `main`：正式主代码，以已验收的 0.8.6 为起点。
- `v0.8.6` 标签：固定保留本次基线，供核对和恢复。
- [`design/start-work` 分支](https://github.com/ma-6C/manjv/tree/design/start-work)：独立的五阶段引导流程原型，使用示例数据，尚未接入正式处理服务。

现有工作台支持“开始连续制作”和“仅合并切分”。连续制作依次执行已开启的 AI 文案、源片字幕修复、画面处理与分集、高光包装、封面、制作记录、成本报告。字幕处理先于重组；已完成的单步合并任务可复用分集继续后续步骤，避免重复编码。

引导流程原型组织为“准备素材 → 确认方案 → 自动制作 → 检查成品 → 导出发布”。它与正式界面分开维护；后续接入应保留“引导流程 / 原版工作台”两个入口。

当前开发源码已移除自绘工程图，改用剪映真实工程与官方窗口截图；详见 [真实工程接入说明](docs/official-project-evidence.md)。已在本机剪映11.6用6秒样片完成打开、播放与截图验证，未据此宣称平台审核通过。

## 当前能力

| 模块 | 已实现的行为 |
| --- | --- |
| 素材管理 | 本地扫描、自然集号排序、自由选集、预检、成片与原片分开保存 |
| 红果接入 | 原生目录和搜索、分享链接定位、选中集与跨页全集连续下载；来源实际返回的入口逐集核验 |
| 下载调度 | 下载与转存/校验/入库流水线；默认最多5集并行；可关闭自动调整；双分段为可选项且默认关闭 |
| 画质与恢复 | 最高可用/1080p/720p选择；保留已完成文件；有上限的断流续传；来源要求等待时暂停 |
| 视频制作 | FFmpeg重组分集、画面参数与音轨处理；GPU实测选择及CPU回退 |
| 字幕 | 本地区域修补、外置video-subtitle-remover适配和可配置云端适配；实际效果取决于所选引擎 |
| AI接口 | 多连接、主备和任务选择；文字、生图、云端字幕适配，密钥仅保留当前会话。视频生成模块已移除 |
| 剪映工程与材料 | 可编辑剪映草稿、导入官方编辑器、实际窗口截图及来源登记；封面、JSON制作记录、成本报告和材料导出 |
| 任务反馈 | 实际处理进度、阶段耗时、暂停/恢复、任务配置快照；刷新保留搜索输入和队列滚动 |

平台发布、剧集提审、广告解锁和收益读取不能由本地制作完成状态自动推定。相关流程按现有适配和人工核对执行。本仓库不承诺源站固定下载倍速或所有GPU型号均已实机验证。

## 本地开发

本次发行使用64位Windows和Python 3.12。先准备独立Python环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe desktop.py
```

也可直接运行服务，在浏览器中通过启动入口访问本机会话。FFmpeg由现有依赖或指定的`FFMPEG_EXE`提供。开发运行与冻结安装版的设备授权要求按现有代码分别处理，不修改发行校验规则。

红果原生功能需要本地`engines/guoapp-core/duanju_core.dll`，其版本和SHA256记录在同目录`manifest.json`。该第三方组件二进制、本地参考工程与Go构建工具不上传本仓库；由组件分发或维护者的参考源码准备，并核对哈希。仅克隆主仓库不等于已经安装所有外置引擎。

本地AI去字幕还需要独立v1引擎包或已配置的video-subtitle-remover环境；本仓库不含模型权重。已有有效引擎可继续使用。

## 检查与构建

```powershell
python tools/verify_build_inputs.py --version v0.8.6
python tools/audit_repository.py
```

第一条逐项核对基线文件；克隆后缺失的生成DLL单独列出。修改功能后哈希发生变化是正常现象，建立新版本记录时应重新执行相应检查。

测试使用隔离数据目录。部分历史验收脚本需要本地回放夹具、Windows工具链、离线引擎或所有者测试授权，仓库不提供这些私人资源。浏览器脚本需准备Playwright和实际浏览器路径。

`build_desktop.py`提供开发打包；`build_hardened.py`编译产品模块并组织正式发行目录，`build_installer.py`生成NSIS安装程序。正式构建需要本地Cython/PyInstaller、C/C++工具链、NSIS及运行库安装资源；现有脚本沿用本地工具目录，不是开箱即用的CI环境。发行签名通过外置签发工具完成，私钥和签发工具不进入仓库。

## 版本保存约定

连续制作入口、自动交接、简洁布局和恢复边界见[连续制作流程说明](连续制作流程说明.md)。这部分为源码功能，未构建新安装包；真实任务、界面和受控发布检查分别记录，最终平台提交仍由本人确认。

稳定代码进入`main`，发行建立独立标签。新流程或较大改动使用独立分支；保留原入口，验证后再合并。不要用旧目录名冒充新源码版本。

本地生成物保留在忽略目录：`data/`、`output/`、`release/`、`tmp/`、`vendor/`、`备份/`和`授权管理/`。提交前检查`git diff --cached`和`tools/audit_repository.py`，不要上传真实素材、账号、密钥、私钥、设备授权码或客户记录。

第三方来源与许可见[ENGINE_REUSE.md](ENGINE_REUSE.md)及相应组件目录。本仓库保留组件自身许可，没有替第三方项目重新授权。
