# 客户 STTN 输出无法读取：排查与源码修复

日期：2026-10-27。客户照片显示：本地 AI 整集去字幕，STTN 时序修复，当前源视频 360×640、约 3:57；第一集输出校验失败，完成数 0/1。

## 已知与未知

截图说明主程序没有读到有效的修复输出，不能据此确定客户是磁盘、编码器、文件损坏还是输入解码问题。尚未取得客户机器上的原始引擎输出或失败 MP4，因此本记录不宣称该客户故障已经现场复现或解决。

已核对实际 v1 离线引擎 ZIP 及其代码：`FFmpegVideoWriter` 将 stderr 丢弃到 DEVNULL，写帧时吞掉 BrokenPipeError，release 未校验非零退出码；后续音轨合成存在捕获错误后回退复制临时视频的路径。于是编码失败可能延迟到主程序校验输出时才报“AI输出视频无法读取”。这是确定存在的软件缺陷，但尚不能将它认定为客户这次故障的唯一原因。

## 源码修改

1. STTN 工作进程内接入严格的 FFmpeg 帧写入与封装适配。使用主程序随包提供的 FFmpeg，不依赖旧引擎独立维护的 FFmpeg 路径；不修改已导入的签名引擎文件和模型。
2. 断管、编码退出码、超时、无帧、无效尺寸及音轨封装失败都明确抛错，保存原始 stderr；不会吞掉失败后继续报告完成。
3. 音轨直接从原片转为 AAC 并与修复画面封装；无声原片也支持。视频流复用，不为合成音轨再次编码画面。
4. 关闭模型复用时仍走同一套严格输出路径，只在单集完成后释放模型进程。
5. 输出检查保留实际 FFmpeg 原因、输出路径、文件大小、引擎输出和调用堆栈。损坏 MP4 可明确看到 Invalid data、moov、解码错误等实际信息。
6. 完整解码通过后才登记成片及检查点；失败集保持未完成，恢复继续复用此前已完成的检查点。

## 验证

- `verify_sttn_output.py`：对现有已导入 v1 离线引擎执行真实 STTN。360×640 的 14 秒带声样片和 2 秒无声样片连续处理，验证完整时长、音轨、全片解码、模型复用及关闭复用的行为。
- 在工作进程中将旧引擎 FFmpeg 定位故意设为不存在路径，验证处理确实使用主程序的 FFmpeg；这个故障注入不修改引擎文件。
- 实际 FFmpeg 写入失败、断管、无帧与奇数尺寸检查，以及缺少编码器路径时的工作进程错误传递。
- `verify_subtitle_full.py`：14 项通过，覆盖损坏输出保留真实原因、连续选集、完整时长、音轨恢复及失败后接续。
- `verify_vsr_pool.py`：10 项通过，含两个真实模型任务、缓存复用、完整解码、停止及空闲释放。
- `verify_task_diagnostics.py`：22 项通过。

真实运行记录位于 `tmp/sttn-output-latest.json`。测试采用同画幅短样片，未使用客户的 3 分 57 秒原视频，不作为客户长视频吞吐或客户具体故障的现场证据。

本轮修改源码，尚未生成新的客户安装程序。客户已导入的 v1 模型在本机验证可继续使用；实际交付仍需对新编译版与安装程序验收。
