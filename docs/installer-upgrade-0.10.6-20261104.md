# 0.10.6安装时可选卸载旧版本

用户希望像IDEA安装向导一样选择卸载旧版。已增加“发现已安装版本”页面，在欢迎页之后、组件选择之前显示。页面列出旧版版本号和安装目录，提供“安装新版本前，先卸载旧版本”勾选项，默认不勾选。返回上一页后保留选择。没有已注册旧版时跳过此页。

检测范围为本安装器在当前用户HKCU中注册的安装。未注册的便携版、其他用户的安装和独立小v喵程序不会自动清理。当前注册结构只记录一个安装位置，不声称能列出所有历史文件夹。

## 执行与数据保留

- 选择页面本身不执行卸载，取消向导不会因此删除旧程序。
- 点击“安装”、完成运行库准备后，才调用旧目录中固定名称的卸载程序；不执行注册表提供的任意命令行。
- 未勾选时直接更新。静默安装默认也不卸载；管理员明确指定`/REMOVEOLD=1`才启用。
- 按NSIS[命令行文档](https://nsis.sourceforge.io/Docs/Chapter3.html)使用最后一个未加引号的`_?=`参数，等待真正的卸载进程退出，支持目录含空格。
- 旧主程序文件无法取得写入访问权、卸载启动失败、返回失败、或旧主程序仍存在时，中止新文件写入。
- 旧卸载器按生成时的明确文件列表移除程序。没有递归清空目录；项目、成片、授权、模型、小v喵用户运行目录及未列入清单的个人文件保留。

## 验证

1. `upgrade-scenarios.json`：17项小型真实NSIS场景检查。含首次安装、默认直接更新、明确保留、勾选卸载、旧文件占用、卸载器失败/缺失、同目录重装和个人数据保留。所有卸载目标均在临时目录，结束后恢复原注册表。
2. `upgrade-ui-report.json`与两个预览截图：实际原生控件核对旧版信息、默认未勾选、切换页面和返回后保留勾选。预览无安装或卸载动作，旧版本号采用示例0.10.5。
3. `installation-report.json`：使用完整0.10.5正式包在隔离目录安装旧版，再运行完整0.10.6正式包选择卸载该测试旧版。30项检查通过；旧程序和卸载器移除，新版2141个发行文件校验通过。旧目录中5类个人测试文件哈希一致，原注册表和快捷方式恢复。
4. `native-ui-report.json`：实际升级后的EXE启动，35项桌面运行检查通过。小v喵134个随包文件校验、真实启动和独立数据库初始化通过，原修复版数据库哈希不变。
5. 编译版小v喵单元检查8项、原有授权兼容检查31项通过。一次并发扫描期间的临时目录重命名出现WinError5，扫描完成后重跑同组8项通过，未因此修改产品代码。
6. `defender-scan.json`：防护保持启用，扫描未发现匹配本版本的检测记录。`build-inputs.json`记录244项输入，最终核对无漂移。

测试中修正了Windows命令行对NSIS`/D=`含空格目录的引用方式。首次测试因整个参数被自动加引号，单个测试标记写到了默认程序目录；已校验标记内容并仅移除该标记，未覆盖或卸载现有程序。后续路径均验证属于临时测试根目录。

相关实现：`installer_upgrade.nsh`、`build_installer.py`。测试：`tools/verify_installer_upgrade.py`、`tools/verify_installer_install.py --version v0.10.6 --upgrade-from-version v0.10.5`。交付整理：`tools/package_release_0106.py`。

小v喵继续随包提供offline-local本地修复版；联网登录、发布和云同步没有新增验收。离线AI引擎不在本次安装包内，沿用原组件导入方式。0.10.5交付包保留，0.10.6单独发布。
