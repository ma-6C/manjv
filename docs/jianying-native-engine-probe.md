## 沿依赖找到的 Windows 实现

历史 Skill 的来源声明引用 [wenshui330/jy-draftc](https://github.com/wenshui330/jy-draftc)。这份上游当前源码已实际检出，固定提交为 `4f705a972da3f042a79dabc8b778e95d31af0a0f`，采用 MIT 许可。它通过独立工具进程加载用户本机安装的剪映引擎；不包含剪映官方运行库。[该版本源码](https://github.com/wenshui330/jy-draftc/tree/4f705a972da3f042a79dabc8b778e95d31af0a0f/src/11.6.0.14552)、[许可](https://github.com/wenshui330/jy-draftc/blob/4f705a972da3f042a79dabc8b778e95d31af0a0f/LICENSE)

本机 `videoeditor.dll` 与该适配版完全匹配：

| 项目 | 实际值 |
|---|---|
| 剪映版本 | `11.6.0.14552` |
| 文件大小 | `72,547,608` 字节 |
| SHA256 | `8CFCBB612CCD946DF974428977B1902736C1DE0AE561E20C26CBD4EA86099CB1` |

## 接入正式工具前的约束

- 首先严格核对实际引擎版本、文件大小与 SHA256；不能用“程序名称相同”代替兼容检查。上游的单次导出入口没有为我们提供完整的外层硬门禁。
- 使用独立子进程、独立工程副本、新的绝对输出路径和外层超时。上游单文件导出会覆盖输出文件，不能直接接受用户已有成品路径。
- 导出后独立检查完整解码、时长、帧数、画幅、音轨和实际画面；不能只看退出码为 0。
- 原生引擎导出、桌面打开、原生窗口截图、本人关联确认和平台审核分别记录。此试验没有解除现有截图归属确认或把草稿复制当作打开完成。
- 所有用户继续使用自己安装的匹配版剪映，不将其运行库、字体、效果包或账号资料放入我们的安装包。

这次已经验证 Windows 11.6 的真实引擎导出可行。尚未完成的部分仍包括正式软件任务/界面集成、其他剪映版本、客户整剧性能、指定桌面工程自动打开和整套平台流程验收。
