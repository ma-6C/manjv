# 整片去字幕开发验收 · 2026-10-24

以 0.8.6 主线为基线，当前为源码开发变更，尚未生成新安装包。

## 行为

- AI 去字幕页面首先显示「当前整集去字幕」「整剧连续去字幕」。前者使用源视频下拉框的完整视频；后者按当前剧集导入顺序处理全部视频。任务中固定视频范围和参数。
- 5 秒、10 秒按钮继续作为短片试处理入口。正式整片任务没有 10 秒上限，也不再受旧配置「前几集」限制；旧历史任务恢复时保留原来的范围。
- 本次使用框选区域修复，覆盖整段时长。最多 8 个选区；仅修改选区内的图像内容，视频重编码仍可能产生选区外的编码差异。
- 页面显示集数、时长、任务进度、已完成文件和播放下载入口；环境校验失败时显示持续的行内错误。
- 保留已完成集数的检查点，失败或暂停后可继续未完成部分。当前未完成的视频重新处理。
- 本地 VSR 输出必须存在、可读取且时长符合原片，才登记完成；原片有音轨而模型输出缺失时，通过视频流复制恢复原片音轨并校验。

## 证据

1. `verify_subtitle_full.py --real-ai --source <自备带字幕视频>`：20 项通过，包括六集连续范围、当前单集、任意选集顺序、缺失引擎、无效输出、中断恢复、音轨恢复及真实 STTN 修复。真实 AI 使用 640×368、30fps 的 36.2 秒循环样片及 12.07 秒片段，分别完整解码 1086、362 帧，均保留音轨。
2. `verify_subtitle_minutes.py`：5 项通过。180 秒、640×368、6fps 压力样片实际经过 STTN-auto，输出 180 秒，全部 1080 帧解码正常，保留音轨，源文件 SHA256 未变。约 172 秒为本次模型启动、修复、校验及截图用时，不含样片构造；不代表 1080p、30fps 或客户硬件的处理速度。
3. `ui-subtitle-full-smoke.cjs`：15 项真实 Edge 界面检查通过，覆盖按钮请求、完整视频范围、两集自动连续、结果播放下载、可聚焦错误及刷新后错误保留、390px 窄窗口和 JavaScript 运行错误。界面范围测试使用本地 delogo，神经网络修复另由上述真实 STTN 测试证明。
4. `verify_production_handoff.py`：32 项既有连续制作/恢复回归通过。

以上验证使用本机 RTX 4060 Laptop 及已有离线 VSR 引擎；没有重新分发模型、修改旧引擎包、调用云端服务或实测客户电脑。测试视频、截图与报告保存在忽略的 `tmp/`，不提交到源码仓库。

## 本地复验

先准备现有本地 VSR 安装记录、FFmpeg 和开发依赖。全部测试使用独立 `MANJU_DATA`，不会更新正常用户工程。界面脚本依赖本机 Edge/Playwright，启动 `test_subtitle_full_ui_host.py` 前先运行核心验收以生成其隔离数据。

```powershell
python verify_subtitle_full.py --real-ai --source "带字幕原片.mp4"
python verify_subtitle_minutes.py
python verify_production_handoff.py
python test_subtitle_full_ui_host.py --seed tmp/subtitle-minutes-latest.json
```

「可以处理几分钟」是时长范围和完整输出能力；不同分辨率、帧率、字幕面积、模型与硬件仍影响耗时和修复质量。本轮没有将低帧率压力样片当作常规片源速度承诺。
