# 发布与提审工作区

本次为开发源码更新，未生成安装包。入口是左侧「推广发布 → 发布与提审」。

## 使用顺序

1. 选择已在本软件制作的剧目；外部成品则展开「从已有成品目录导入」，先识别剧目根目录，再勾选导入。
2. 填写实际剧名、简介、制作方、总集数、试看集数、剧目类型和制作成本。制作成本单位为元。
3. 从「剪映工程与截图」采集本剧真实官方窗口截图作为工程证明；再按用途补充封面、分镜截图、成本报告图片、报告文档，以及需要的授权证明。附件可通过本机文件选择器多选。
4. 点击「保存并检查」。缺项在清单和对应字段显示，可直接定位。默认分镜数量是本地准备方案，不是对当前平台规则的声明。
5. 导出提审资料目录，或按账号打开官方后台。首次登录由本人在官方页面扫码。
6. 进入账号实际有权限的新建剧集或提审表单，再点「检测当前页面」。识别到明确表单后，可辅助填写字段及选择用途明确的附件。
7. 在网页核对上传、转码、声明和全部表单内容，由本人最终提交。根据实际后台回执，在软件中保存核对说明和状态。

「切片分发」保留原来的普通视频上传引擎、账号选择和提交前清单，默认草稿行为保持原配置。

## 数据与结果

- 只使用明确登记的当前成片，不将原始视频、试处理短片自动作为成片。最新代成片丢失时，列出缺失，不回退旧代。
- 总目录识别避免把「分集、工程记录、jy、fenjing、zhengming」等材料目录分拆成独立剧目。
- 图片做可解码检查；报告做文件类型检查；视频按文件名自然排序，并复用文件 stat 对应的探测缓存。
- 工程证明只接受服务端已登记、本人确认且哈希匹配的剪映官方窗口截图。旧自绘图、拼接页和未核验的手动图片不会自动通过；历史其他来源记录与图片保留，但不再计入当前工程证明。
- 检查通过仅表示本地准备方案齐全。图片真实性、版权、当前平台适用性仍由提交人核对。
- 导出在后台运行，反馈实际复制字节。包内有相对路径、SHA256 和字段清单；原文件保留，每次新建独立目录。
- 导出不写「已经发布成功.txt」。导入历史成功标记也不会据此判为已提交。
- 账号后台采用独立本地浏览器资料目录；提审与普通上传资料分别保存。不会读取或注入其他浏览器 Cookie，不伪造浏览器指纹。
- 登录状态来自当前可见页面，不凭 URL 或 Cookie 文件存在就标为已登录。重启后的旧检测状态会变为待重新检测。
- 辅助填写只匹配明确的字段标签；不覆盖另一部剧已有的表单，不代勾版权承诺，不点击最终提交。未知控件逐项列为待手工核对。
- 选择附件不代表上传、转码完成。后台辅助结果固定区分 `submitted:false`、`uploadCompleted:false`。
- 用户回填结果标为 `source:manual`、`platformVerified:false`。相同账号已记录提交的同一资料版本，会阻止重复辅助上传并要求先核对后台。
- 关闭软件会停止未开始的操作；中断记录需要核对后再操作，不自动重试可能涉及提交的步骤。

## 实现与复验

- `publish_materials.py`：检查、目录识别、清单导出。
- `publish_workflow.py`：配置、任务、账号辅助与结果记录。
- `publish_browser.py`：正常可见 Edge/Chrome 窗口，沿用现有发布浏览器依赖。
- `web/publishing.js` / `publishing.css`：两个发布入口、资料表单、检查反馈、进度和结果。

```powershell
python -X utf8 verify_publish_materials.py
python -X utf8 verify_publish_workflow.py
python -X utf8 verify_publish_browser.py
# 可选：仅打开真实官方匿名登录页并检查，不登录、不上传、不提交
python -X utf8 verify_publish_browser.py --live
python -X utf8 test_publish_ui_host.py
# 另一个终端；默认读取上面的隔离预览元信息
node verify_publish_ui.cjs
```
